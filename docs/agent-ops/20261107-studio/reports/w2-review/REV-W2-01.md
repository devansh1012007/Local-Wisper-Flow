### BLOCKER-2 — Production engine worker never started: dictation, stats, and transform all dead (`Start`/`ProcessOne` absent, `RunEngine` dead)

- **Where:** `src/main.cpp:272-692` (constructs `DictationEngine engine(...:496-506)`, forwards hotkey events via `engine.PostEvent(:626)` and `engine.Stop(:678)`, but never `engine.Start()` nor `engine.ProcessOne()`); `RunEngine` definition `:197-268` has no caller (grep-verified). Until then, re-scope Wave 2 verdict to "headless logic accepted, production liveness rejected."

### MAJOR-1 — Transform LLM is synchronous with no timeout and no `RequestCancel()` propagation — one hung call stalls the worker

- **Where:** `DictationEngine.cpp:734-740` (`result = transform_llm_->Process(original, prompt);` inside `try{...}catch(...)`), `RequestCancel`/`HandleCancel` never calls `transform_llm_->RequestCancel()`.
- **What:** `CommandModeController::Run` (`:97-111`) runs the LLM on a `WorkerQueue` with an 8000 ms timeout + `RequestCancel()` + 3 s grace, restoring the clipboard on timeout. `HandleTransform` calls `Process` inline on whatever thread pumped it (`Run` worker or `ProcessOne` test caller). If `LocalLlamaProvider::Process` blocks (warmup, long completion, deadlock), `cancel_requested_` is only checked **after** `Process` returns (`:747-751`), and `ILlmProvider::RequestCancel()` (virtual no-op default, `ILlmProvider.h:10`) is never forwarded — so "cancel during LLM" is cooperative-only in the post-return sense, not preemptive. `E2`'s `HookLlm::during → RequestCancel()` test passes only because the hook returns immediately; it does not emulate a hung LLM. Meanwhile the worker is wedged: queued `PttPress`/`PttRelease`/`PasteLast` and further `PumpTransform` all wait behind `Process`, while the UI thread dutifully returns from `RequestTransform` (atomic) — the "non-blocking UI" test measures the wrong queue. `Quit` at `Run:155-157` (`break` before `PumpTransform`) additionally discards a pending transform silently.
- **Fix direction:** mirror command mode: run `Process` under a timeout worker (`WorkerQueue`/`future`), forward cancel (`transform_llm_->RequestCancel()` from `RequestCancel`/`HandleCancel`), restore clipboard on timeout/failure, and add a hung-LLM regression test (fake that never returns; assert dictation event still processes and clipboard restored).

### MAJOR-2 — Unbounded selection size feeds `Diff` O(n·m) table — DoS/crash before `RestoreClipboard` (exception escapes worker)

- **Where:** `TextDiff.cpp:89` (`vector<vector<size_t>> table(n+1, m+1)`), called via `TransformDiffStore::Put` (`TextDiff.cpp:146-156`) from `HandleTransform:759` (`transform_diffs_.Put(original, result, ...); selection_->RestoreClipboard();`).
- **What:** nothing caps `original` from `CaptureSelection()`. A user who selects a whole file/log (1–10 MB → 100k–1M tokens) makes `Diff(before, after)` allocate a table of (t+1)² × 8 bytes — 100k² is 80 GB transient — `bad_alloc` (or OOM-killer on CI) thrown from `Put`. `Put` is **after** `InjectText` and **before** `RestoreClipboard`: success-path restore is skipped when `Put` throws, and `Run()`/`ProcessOne()` have no catch-all, so an instrumented worker terminates via uncaught exception (default `std::terminate` from a `noexcept`-violating thread entry). The same class of throw via `BuildTransformPrompt` allocation, `transform_diffs_.Put` `Diff` OOM, or `CaptureSelection()` throwing (clipboard race) leaves the clipboard unrestored — the `catch(...)` coverage starts only after capture/transform, so "restore on every branch" (E2 claim) does not hold for exception branches. `TextDiff` NIT-2 (W1) warned "a 10k-word paste is ~800 MB" — Wave 2 wires that exact sink to unbounded clipboard input, past the dictation-scale assumption that held for `ProcessWithStats` (≤120 s of speech).
- **Fix direction:** cap selection size before LLM/Diff (e.g., reject >8–50 k chars with "Transform failed"), and/or make `Diff` fail-soft above a token threshold (return `valid=false` or truncated diff, never OOM). Move `RestoreClipboard()` before/around `Put` or use RAII guard for the captured window; wrap `CaptureSelection()`+`Put` so a throw still restores and maps to a generic error rather than terminating the worker.

### MAJOR-3 — Clipboard save/restore is text-only and not all-branch exception-safe; image loss is silent

- **Where:** `os/WindowsTextInjector.cpp:366-470` (`CaptureSelection` saves/restores only `CF_UNICODETEXT`; `RestoreClipboard:439-469` `EmptyClipboard` + `SetClipboardData(CF_UNICODETEXT)`; empty-save path Empties and does not restore formats); `DictationEngine.cpp:725-761` (call sites above).
- **What:** if the user had an image/file/drop on the clipboard, Ctrl+C inside `CaptureSelection` overwrites it; `RestoreClipboard` reinstates only the saved text (empty string → `wide_size==0` → clipboard left empty). The image never returns. `E2 §28` discloses this as "same as command mode; OS-layer upgrade belongs to Wave 4" — honest but incomplete: the brief/spec asked "save clipboard (all formats possible)" and `WindowsClipboardInjector::RestoreClipboardFormats` (dead, `:122,247`) already implements the multi-format pattern; reusing the live seam was a choice, not a necessity, and should be a tracked decision (clipboard image loss is user-visible data loss). Combined with MAJOR-2's exception gaps, "restore on every branch (image+text)" currently means "restore text on non-exception branches, lose images always."
- **Fix direction:** decide explicitly (track in MISSION/ledger): either copy the multi-format save/restore into `WindowsSelectionCapture` (test with `CF_DIB`/`CF_HDROP` fakes), or document image-loss as known limitation in the transform UI/manual checklist. At minimum, never upgrade an image-clipboard to empty text silently — preserve or warn.

### MAJOR-5 — Thread-safety: `scratchpad_target_` plain bool races on any future toggle; `EngineSettings` by-value copy makes all ApplySettings timings dead; transform conflict set goes stale

- **Where:** `DictationEngine.h:132` (`bool scratchpad_target_`; worker read at `DictationEngine.cpp:611`, setter at `:259-261` plain store); `main.cpp:576-590` (ApplySettings mutates local `settings.*` — engine holds a ctor copy `DictationEngine.h:112`); `main.cpp:509` (`transforms.SetHotkeyBindings` once at startup, `ApplySettings` never refreshes it).
- **What:** (a) Wave 2 main sets `SetScratchpadTarget(false)` once before `PostEvent` — safe today. Wave 4 will "toggle the flag" from the main thread (E3 §9) while the worker reads it in `Record` gating — plain `bool` cross-thread read/write is a data race (UB). Should be `std::atomic<bool>` now (one-line), before Wave 4 touches it, as with `pending_transform_slot_`. `stats_/active_window_/app_context_/transform_*` pointers have the same single-write-before-start contract but are never toggled post-start — acceptable, but `scratchpad_target_` is the one designed to be runtime-toggled. (b) `EngineSettings settings_` is copied in the ctor; `ApplySettings` mutates main's local `settings` (`min_hold_ms`, `quiet_speech_boost`, `streaming_*`, etc.) — those mutations never reach the engine. `spoken_`, `snippets_`, `overlay` hot-applies **do** work (live references), and Wave 2's two new hot-applies (`usage_stats.SetUsageStatsEnabled`, `SetScratchpadVisible`) do work, but the pre-existing dictation timings silently no-op. Wave 2 kept the shape (copy-pasted the loop) without naming it. (c) `transforms.SetHotkeyBindings(hotkey_bindings)` conflict detection is a startup snapshot; after a `StartLearnHotkey`+`ApplySettings` hotkey change the transform slots' conflict set is stale until restart (only hotkey router is refreshed).
- **Fix direction:** make `scratchpad_target_` atomic; add `engine.SetSettings` (or update by reference) and refresh `transforms.SetHotkeyBindings` in `ApplySettings`; add one hot-apply regression test mutating a timing through the same path the Settings UI will use.

### MAJOR-6 — Secrets hygiene: `api_keys.json` plaintext Electron + `.bak`/`.bad`/`.tmp` ghosts retain keys indefinitely

- **Where:** `ApiKeyStore.cpp:104-139` (`PersistLocked`: `.tmp` write, `.bak` copy of previous file on every `Set`, rename), `:68-101` (`LoadLocked`: corrupt → rename to `.bad` with `ec` unchecked, keys remain in `.bad` forever), `tests/test_apikeystore.cpp:15-21,102-218` (temp dirs never cleaned).
- **What:** plaintext at rest is by plan (§3.7, separate file, never `config.json`) — accepted — but three retention behaviors go beyond plan: (1) every `Set` leaves the **previous** key in `.bak` indefinitely (no rotation/deletion); a user who removes a key keeps it recoverable from `.bak`; (2) a corrupt file's keys are preserved in `.bad` forever (forensics vs secret hygiene trade-off E3 chose `.bad` over delete — correct for stores, debatable for secrets, and never disclosed on the Privacy page); (3) `Set` failure rollback restores memory but leaves `.tmp` on early-exit paths where `PersistLocked` already removed tmp — consistent — but the **secondary** retry in `LoadLocked` (Windows close-before-rename analogue at `NotesStore.cpp:167-175` has a fallback remove+retry) is missing in `ApiKeyStore` (rename `ec` ignored twice), so a pre-existing `.bad` from a prior corruption silently pins the corrupt file in place and `Load` reports empty forever. Tests compound it: each case leaves `lwf_apikey_*` + `api_keys.json` (fake keys `sk-secret-xyz-123`, `key-one`, etc.) in `%TEMP%` across runs (remove-before at start only, never after).
- **Fix direction:** treat `.bak`/`.bad`/`.tmp` as secret-bearing: either DPAPI/`CryptProtectData` (full fix, OS work — Wave 4?), or at minimum shorten retention (delete `.bak` after successful `Remove`, delete `.bad` after user acknowledgement, or encrypt-on-disk flag), and add `remove_all` cleanup post-case in tests (already E3's own pattern for stats files). Privacy page/About must disclose the plaintext store + ghosts or the plan must stop claiming "redacted from every stored log line" as the whole story.
- **Note:** `ResolveApiKey` itself leaks nothing (no log, checked), `HandleTransform` errors are generic (no `e.what()`), test `sk-secret-xyz-123` values appear in doctest `values:` trace on failure — synthetic canary, not a real secret; still, never paste a real key into a test fixture per this pattern.

### MINOR-1 — Preamble validator gaps: boundary set misses `.`/`?`/tab, `Here's` accepted, quoted stubs pass

- **Where:** `DictationEngine.cpp:74-98` (`after` ∈ {` `,`:`,`,`,`!`} only), vs `CommandModeController.cpp:13-36` (same boundary, 5-word list incl. `here's`,`as an ai`). Tests cover `Sure …`, `Here is …`, `Certainly!`, `Surely` (correctly allowed by boundary).
- **Breaks:** `Sure. …`, `Sure? …`, `Sure\t…`, `Sure—…` are accepted and injected with preamble; `Here's the result:` (contraction, same preamble class per command mode) accepted; leading `"`/`` ` ``/markdown fence (`"Sure, …`) passes because `TrimCopy` strips only whitespace and `StartsWithPreamble` searches from first non-space. The two validators already diverged (3 vs 5 words) and will drift.

- **What:** copying "hello world" then selecting the same "hello world" elsewhere and pressing transform yields a timeout → `RestoreClipboard` (internal `:410`) + `nullopt` → "Select some text first", although a selection exists. Real impl burns 300 ms + 20 ms polling before discovering it. Same as command mode, pre-existing, but transform makes it the **only** report path (no fallback prompt for "same-as-clipboard"). Test suite never sets `selection == clipboard`.
- **Fix direction:** document as known limitation or read clipboard-change sequence number / clear-clipboard-re-copy trick; add one test pinning the equal-case behavior.

### MINOR-3 — `ProcessWithStats` `words_corrected` counts more than cleanup (snippets, spoken commands, case/punct)

- **Where:** `TextPipeline.cpp:107` (`Diff(raw, final_text)` over the whole pipeline: Normalize → cleanup(LLM) → `Enforce` → snippets → `NormalizeLines`).
- **What:** snippet expansions (`btw`→`by the way` = 3) and spoken-command expansions count as "corrected words" even though the user spoke them deliberately; `hello`→`Hello` (case) and punctuation count because `Tokenize` splits only on whitespace. E1 §11 discloses it; definition is stable and pinned, so not a bug against the brief ("between raw and cleaned"), but Insights consumers reading "words_corrected" as LLM/dictionary fix rate will over-count. `app_profile` is set on the record but ignored by `StatsStore::Record` (record field dead — "recorded for debugging" in E1 §4 is overstated; stats persists `process_name` only, never `raw_text`/`final_text`).
- **Fix direction:** annotate the field in `StatsStore.h` ("pipeline-wide delta") or split diff (raw→pre-snippet vs raw→final) if Insights needs cleanup-only. No code change required if the product definition is whole-pipeline.

### MINOR-4 — Stats duration attribution is inject-day bucketing; `timestamp_local=0` + queue latency inflate/deflate by design

- **Where:** `DictationEngine.cpp:609-613`, `StatsStore.cpp:151-155` (`Record` `NowSeconds()` when `timestamp_local<=0`), `ProcessOne`/`PostEvent` queue timestamps from `IClock` (steady).
- **What:** `DateKey` for a dictation starting 23:59:58 and finishing 00:00:03 buckets to the **inject** day, not press day (dictation-length edge, low risk, E1 correctly flags as [ASSUMED] press-day alternative needs wall clock `BeginCapture` can't supply). `now_ms` is the event-stamp time (`PostEvent` `clock().NowMs()`), not release-wall time: hotkey→queue→worker latency (main loop 8 ms sleep + `Run` `PopFor(20)` ≈ up to ~30 ms) is counted as speaking time. FakeClock tests are deterministic (120 ms pinned) so this never surfaces. Not worth fixing beyond documenting the bucketing rule for Insights.

### MINOR-5 — Overlay note geometry: integer poll vs float draw 1 px mismatch; source-scan test is CWD-fragile

- **Where:** `Overlay.cpp:303-318` (`(poll_win_w - poll_dot_px)/2` integer, `(poll_dot_px - poll_note_px)/2`), `:402-404,424-426` (`(display.x - dot)*0.5f` float, `dot_min.y + (dot - note_size)*0.5f` float); `tests/test_scratchpad_target.cpp:132-157` (`ReadSource("src/ui/Overlay.h")` relative, not `LWF_SOURCE_DIR`).
- **What:** at odd window widths / fractional DPI the poll rect can be 1 px off the drawn `InvisibleButton("##note")`, causing one spurious wake/ miss — E3's "self-corrects per R-W2-005" reasoning is sound (re-polled every idle tick), but there is no pixel assertion (source-scan only proves string presence, not hit alignment). CWD fragility: `ctest` sets `WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR}` so it passes in CI [RAN], but running `build/lwf_tests.exe` from `build/` (the natural dev loop) makes `ReadSource` return empty → 4 `REQUIRE_FALSE(overlay_h.empty())` failures. Only one test in the suite uses relative `src/` paths; `test_errors.cpp:118` correctly uses `LWF_SOURCE_DIR`.
- **Fix direction:** use `std::filesystem::path(LWF_SOURCE_DIR)` in `ReadSource`; add one headless geometry unit (extract the note-rect computation or assert poll/draw formulas equal). No production change needed if the 1 px tolerance is accepted.

### MINOR-6 — `ApiKeyStore` small correctness gaps: unchecked `.bad` rename, adjacent stores' close-before-rename fallback missing for secrets

- **Where:** `ApiKeyStore.cpp:79-87` (`rename(path, path+".bad", ec)` then `keys_.clear()` regardless of `ec`); contrast `NotesStore.cpp:167-175` (remove+retry fallback on `rename_ec`).
- **What:** on Windows, `rename` over an existing `.bad` (second corruption, after a prior `.bad` was never cleaned) fails, `ec` is discarded, and the corrupt original stays at `path_`. Next `Load` repeats the cycle, keys stay empty, and the app has no signal the forensic path failed. `StatsStore::LoadLocked`/`DictionaryStore`/`SnippetStore` have the same unchecked pattern (W1 MINOR-7), but secrets magnify it: the file that looks like an empty store is actually the quarantined secret again. Also `it->get<std::string>()` at `:96` is safe only because `is_string()` was checked at `:93` — fine — but `json.begin()` iteration on a moved file handle without `file.close()` before `LoadLocked` returns on the non-corrupt path relies on the caller closing at `:91` (correct, but asymmetric with the early-close paths).
- **Fix direction:** check `ec`, apply the `NotesStore` remove+retry fallback, log (counts only) or surface a sentinel. One-line.

### MINOR-7 — Empty-string env and store ambiguity; consent reason always names the env var

- **Where:** `ConsentGate.cpp:50-61` + `EvaluateCloudConsent:77-82` (`reason = env + " is not set"`).
- **What:** `GNANI_API_KEY=""` (explicit empty) resolves to `""`, identical to missing — `ApiKeyMissing` fires and names the env even when the store path was consulted first (e.g., store empty + env set → found; store key removed + env unset → message still blames env, which is correct for store-first precedence but confusing for store-configured users). For `openrouter` (no env), `ResolveApiKey` correctly returns store-only, but `ApiKeyEnvFor("openrouter")==nullptr` means `EvaluateCloudConsent("openrouter")` hits `ProviderUnknown` before key checks — the Wave 4 OpenRouter consumer must not route through `EvaluateCloudConsent` or it will never reach "allowed". Not a Wave 2 runtime break; a trap for the next consumer.
- **Fix direction:** document `ResolveApiKey` precedence + empty-string rule in the header; give callers a `store_present` vs `env_present` distinction if the UI needs to say "save a key in api_keys.json" vs "set env".

### MINOR-8 — `TransformDiffStore::Get/Has` copies full diff on every poll; retention clock hand-rolled

- **Where:** `TextDiff.cpp:158-171` (`Has` = `Get().valid`; `Get` copies `TransformDiff` incl. `diff.tokens` vector + `before`/`after` strings under lock), `kRetentionMs=40000` (`:41`).
- **What:** `HasTransformDiff()` (the Win+Alt+O poll path, Wave 4) deep-copies the entire diff + both texts on every 40 s-window check, even when the caller only needs `valid`/expiry. At transform scale (short snippet) fine; pathological only for huge selections (see MAJOR-2). Expiry `now - captured > 40000` keeps a diff whose clock went backwards (`captured_ms` in future) indefinitely valid; `RealClock` is steady (never backwards) so prod is safe, `FakeClock` in tests only moves forward — cosmetic.
- **Fix direction:** add `HasNoCopy(now)` that checks `valid && now-captured<=kRetentionMs` under lock without copying; keep `Get` for the viewer.

### MINOR-9 — Leaked test artifacts + leftover `.tmp`/`.bak` on failure paths

- **Where:** `tests/test_apikeystore.cpp:15-21` / `test_scratchpad_target.cpp:19-25` (remove-before only), `tests/test_engine.cpp:StatsPath` (`std::filesystem::remove(path)` before+after in most cases, but `StatsStore` `.tmp` on persist failure not asserted/cleaned).
- **What:** `lwf_apikey_*` and `lwf_scratch_*` dirs accumulate in `%TEMP%` across runs (each case `remove_all` at start, never at end) including `api_keys.json` with fake keys. Not a prod leak, but CI runners accumulate them and a developer grepping `%TEMP%` for secrets finds canaries. Same pattern as W1 stats tests. One-line cleanup in a fixture destructor would close it.
- **Fix direction:** `remove_all` in a teardown guard; optional.

### NIT-2 — `BuildTransformPrompt` "sentence already present" check matches the selection text too

## 4. Optimizations (measurable, not stylistic)

1. **`Has()` copy avoidance (MINOR-8):** `TransformDiffStore::Has` → lock-check without copying tokens. At 60 fps Win+Alt+O polling this removes a string+vector allocation per tick. Trivial fix, no behavior change.
2. **Selection-size cap before LLM (MAJOR-2/4):** clamp/ reject selections above e.g. 16–50 k chars with "Transform failed" before calling `Process` or `Diff`. Bounds both LLM context blow-up and the O(n·m) table — strictly cheaper than handling OOM after.
3. **Locale-independent lowercasing in `StartsWithPreamble`:** manual `u+32` is fine, but the double copies (NIT-1) cost a `reserve+push` per validation. `rfind(candidate,0)` on a lowercased copy is O(n); early `find_first_not_of` + prefix checks would be enough. Not hot (once per transform), listed only so the shared helper gets it right.
4. **No premature diff preallocation:** `ProcessWithStats`/`Put` compute `Diff` unconditionally after injection succeeds (persist diff for 40 s). Even with MAJOR-2's cap, a 2k-word selection still builds a 4M-entry table (32 MB) per transform for a viewer that only needs token ops. A Myers/Hirschberg fallback or token-count ceiling (W1 NIT-2) pays off here first.
