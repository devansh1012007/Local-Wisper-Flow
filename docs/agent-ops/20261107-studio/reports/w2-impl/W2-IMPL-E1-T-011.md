## 4. Phased changes executed
### Phase 1 — TextPipeline ProcessResult (WRITE-SET src/core/TextPipeline.{h,cpp})
DECISION: additive struct + differently-named method. C++ cannot overload Process by return type alone, so `ProcessResult{std::string text; int64_t words_corrected=0; int64_t dictionary_fixes=0;}` + `ProcessResult ProcessWithStats(const std::string& raw)`; `Process(raw)` delegates to `ProcessWithStats(raw).text` (single Enforce call total, never two). CONTRACT posted to COMMS for E3/E2 consumers.
- words_corrected = `diff.replaced + diff.inserted + diff.deleted` where `diff = lwf::Diff(raw, final_text)` [VERIFIED src/core/TextDiff.cpp:131-143 defines replaced=min(ins,del)]. Algebra: this equals max(total_ins, total_del) — a 1:1 swap counts 1, a pure 1-word insertion/deletion counts 1 (replaced-only would count 0 and hide LLM-added words). Pinned by test "pipeline words corrected counts inserted words from cleanup" (ScriptedLlm adds brave → 1). INVARIANT: identical raw/final → 0 regardless of whitespace-only diffs (TextDiff tokenizes on Unicode White_Space [VERIFIED src/core/TextDiff.cpp:10-21], so whitespace normalization never inflates).
- dictionary_fixes = fix_count from the single existing Enforce call: `Enforce(cleaned, true, &dict_fixes)` (Wave 1 single-pass [VERIFIED src/core/PersonalDictionary.cpp:279-358] copies words/replacements under mutex, replacements rebuild + word-phase token rebuild, count only on actual change). Never re-runs Enforce for counting (brief §3). If dictionary null/not-loaded, 0 — same gate as before.
- Guard-rejection semantics (INV §10-4 pinned): when DictationCleanup::ApplyGuards rejects, cleaned equals trimmed sentineled text, so words_corrected reflects only dict+snippet deltas, not the rejected LLM delta. Rejection itself is not counted as a correction. Deterministic and documented; InsightsModel math stays stable.
- No header->TextDiff coupling beyond .cpp include (TextDiff.h pulled only in TextPipeline.cpp).
