### Options for the provider seam
1. `OpenRouterProvider : ILlmProvider` over injected `IHttpTransport&` (CHOSEN). Mirrors Muse/Gnani providers; production injects `WindowsHttpClient` (the only real transport); tests inject a scripted fake. No sockets, no `windows.h`, no `winhttp` in the new TU — keeps the no-network gate honest (file contributes zero `winhttp|wininet|wsastartup...` hits; see D4/C2).
2. New `IHttpTransport::Get` / verb field for model-list or health GET (REJECTED — scope creep + seam growth the brief forbids silently growing). Vendor docs confirm chat completion is POST-only; GET `/api/v1/models` would only serve discovery UX not in C1. Provider skips health checks entirely (degrade: construction never touches the network; first `Process` is the first egress).
3. Implement `IInferenceProvider` (REJECTED). INV-keys-openrouter §5 verified wrong seam: that interface demands audio `Transcribe`; cleanup/transform are text→text. Would mislead `SttRouter` ownership ("cleanup stays local" SttRouter.h:27) and duplicate the STT fallback router.
4. Direct WinHTTP inside the provider (REJECTED). Bypasses the single network seam, duplicates session/connection/timeout handling, puts `windows.h` in `src/llm` (hygiene failure). Explicitly forbidden.

### Options for text→messages mapping
Vendor Request (verified): `{model, messages: [{role:"system"|"user"|"assistant", content}], ...}`. Caller contract is `Process(text, system_prompt)` where `system_prompt` already embeds DictationCleanup's "Fix grammar..." + sentinels + addendum + "Text: <raw>" (ComposePrompt) OR command/transform's edit instruction. Two defensible mappings:
1. system→system, text→user (CHOSEN). Preserves instruction hierarchy as the vendor intends; keeps `system_prompt` as authoritative system content exactly as LocalLlamaProvider's `BuildPrompt(system + "\n\n" + text)` concatenated them. Empty `system_prompt` → omit the system message (vendor treats absent system as valid; avoids empty-system edge).
2. Concatenate `system_prompt + "\n\n" + text` into a single user message (REJECTED). Loses role separation, degrades instruction-following on strict providers, and diverges from the documented schema without benefit.
`stream:false` is omitted (vendor default is non-streaming; explicit `false` is equivalent — omitted to keep golden body minimal and stable).

### Options for typed-outcome surfacing under a string-only interface
`ILlmProvider` cannot return errors. Three candidate contracts:
1. Throw `HttpTransportError` / custom exception and let callers catch (REJECTED). Brief requires "without throwing across seams"; LocalLlamaProvider *does* throw, but its throw is already caught-and-converted by all three callers. Introducing throw for a *network* path means every vendor hiccup becomes an exception the UI thread must not see — the STT precedent is the opposite: `ISttProvider::Transcribe` "never throw for wire failures — they return them on the result" (ISttProvider.h:78-81). Mirror it: never throw for wire failures.
2. Return empty string on any failure + expose `LastOutcome()` on the concrete class (CHOSEN). Empty is already the failure signal every caller handles: DictationCleanup `ApplyGuards` rejects empty → raw (no guard-rejection ambiguity: provider failure is NOT a guard rejection); CommandMode/Transform treat empty as `LlmFailed` with clipboard restore. `LastOutcome` carries the typed category + redacted detail + http_status + latency for logs/metrics without changing the interface. Tests assert both halves (return value AND outcome).
3. Return `text` unchanged on failure (REJECTED). Indistinguishable from "model echoed input"; would count as success, bypass error observability, and reintroduce symptom-masking (the "exactly today" behavior for local failures is exception→raw, not echo).

### Options for timeout values
The single shared `llm` instance serves three callers with different budgets: DictationCleanup `cleanup_timeout_ms` (default 2000, schema 200..30000), CommandMode hardcoded 8000 (CommandModeController call site :598 `Run(raw, 8000)`), transform `transform_llm_timeout_ms_` default 8000 (DictationEngine.h, W2-IMPR-01). The provider cannot know which caller is asking (no call-site param in the interface), so per-caller tuning inside the provider is impossible without interface change (forbidden). Design: provider `timeout_ms` setting (default 8000, documented) passed straight to `HttpRequest.timeout_ms`; each caller enforces its own outer `wait_for`. For the 8000 callers the budgets align; for cleanup the outer 2000 wins and the provider's in-flight Post is bounded to whichever fires first — i.e. effective timeout = min(provider, caller). The 3s drain grace in DictationCleanup absorbs a Post that was already sent. 8000 is NOT a provider-internal `wait_for` (that would need a thread inside a worker thread); it is the transport timeout only. See D3/D4.

## D2 Invariants and contracts preserved

1. **Local default is byte-identical.** `llm_provider=local` (schema default, SettingsStore.cpp:69) takes the exact existing branch: PassthroughLlm → LocalLlamaProvider iff path loads; `cleanup_llm_available`, `cleanup.SetEnabled`, startup errors/logs unchanged. The OpenRouter branch is strictly additive (`else if (llm_provider=="openrouter")`) and only reachable when the operator has opted in. `openrouter_model` is a new additive schema entry (default ""), unknown keys preserved on save (existing mechanism untouched).
2. **ILlmProvider semantics preserved.** `Process` remains synchronous, caller-thread-blocking, non-reentrant (serialized by `mutex_`, mirroring LocalLlamaProvider:95). `RequestCancel` is an atomic store; never blocks, never throws. No new virtuals on `ILlmProvider`.
3. **POST-only, single request per Process.** One `IHttpTransport::Post` per `Process` call (no retries, no fan-out — one-way fallback ownership stays caller-side: cleanup→raw, command/transform→error+restore). No GET, no health ping, no retry-after sleep (no timing hacks, per Standing Orders). `HttpRequest{host, path, headers, content_type="application/json", body, timeout_ms}` is the entire egress surface.
4. **Never throws across the seam for wire failures.** All vendor/transport failures → typed `LastOutcome` + empty return. Only programming errors that already throw upstream remain: empty `api_key`/empty `model` throw `std::runtime_error` at construction (mirrors MuseRequest.cpp:28-33 "api key/model is required"), so main.cpp catches them at startup and degrades to passthrough+disabled-cleanup rather than post-construction surprise. `Process` itself never throws for any vendor/transport condition; even JSON parse failures are outcomes (`Malformed`), and `std::exception` from the transport is normalized to `Network`.
5. **No text or key in any log or persisted detail.** Detail strings are built from status + code + vendor `message` only, then passed through `lwf::RedactSecret(..., api_key)` + `lwf::RedactAuthValues(...)` in that order (STT precedent: GnaniProvider.cpp:91, MuseProvider.cpp:81). Request text is never logged. `Log::` lines carry `provider=openrouter status= error= bytes= latency_ms=` plus redacted `detail` on failure only.
6. **Key custody: store→env, never config.json.** Writer/reader is `ApiKeyStore` (`api_keys.json`, same directory as config.json) with environment fallback `OPENROUTER_API_KEY` read in main.cpp (store first, env second — D3 order). The key is never written to `config.json`, never stored in SettingsStore, never placed in `LastOutcome.detail` unredacted. Constructor takes the resolved key by value into settings (same as Gnani/Muse); there is no later re-read, so rotation requires restart (documented, matches STT snapshot semantics at main.cpp:419).
7. **File-write ban respected.** `src/llm/OpenRouter*` contains zero `ofstream|fopen|freopen|CreateFile(` (would trip check_no_network line 25). No journaling, no caching to disk.
8. **No `windows.h`/`winhttp.h` outside src/os + WindowsHttpClient.** Provider includes only `core/ILlmProvider.h`, `stt/cloud/IHttpTransport.h`, `core/Redact.h`, nlohmann/json, std headers. Hygiene endpoint rule: host string is `openrouter.ai` (no `api.` prefix) so `check_hygiene.sh:61` (`api\.(vachana\.ai|elevenlabs\.io|meta\.ai)`) does not fire; the no-network endpoint gate is extended to cover `openrouter\.ai` with an `src/llm/OpenRouter` carve-out (C2).
9. **Threading: worker-thread only, never UI.** `Process` blocks the caller (cleanup WorkerQueue thread or engine worker thread for transform/command). It is never invoked from the synchronous UiBus drain (main.cpp:597-666). A `std::mutex` serializes concurrent `Process` calls, so a slow OpenRouter response cannot run two POSTs concurrently even if cleanup and transform overlap.
10. **Oversize / hostile input bounded before the wire.** Empty `text` returns empty without a request (mirrors LocalLlamaProvider:91). Text is sent verbatim (UTF-8 JSON string); no transformation (whitespace, quotes, Unicode preserved — guards stay caller-side). No size cap inside the provider (cleanup input is one dictation; transform input is pre-capped at 8000 chars by the engine), but body is built with nlohmann (throws only on OOM-level failure, normalized to `Network` outcome — no path can throw).

## D3 Failure-mode table (typed outcome → caller-visible effect)

Classification function (provider-local, mirrors `ClassifyHttpStatus` semantics without importing the STT enum into the LLM layer):
`401/403→Auth` (403 covers moderation/guardrail block per vendor errors doc — classified as Auth because the key is valid but the request is refused; caller effect identical to auth: fail to raw, no retry), `402→Auth` is NOT in the table below because 402 (insufficient credits) is an account/key state — mapped to `Auth` with `detail` naming credits (vendor: "insufficient credits. Add more credits"); `408→Timeout`, `429→RateLimited`, `413→InvalidRequest` (payload too large), `>=500→Server` (includes 503 "no provider available"), `400/404/412/422→InvalidRequest`, other 4xx→`InvalidRequest`, 3xx/other→`Unknown`. `error_type` stable strings from vendor typed-error table are preferred when present (`authentication→Auth`, `payment_required→Auth`, `rate_limit_exceeded→RateLimited`, `timeout→Timeout`, `server/unmapped→Server`, `provider_overloaded/unavailable→Server`, `invalid_request/invalid_prompt/context_length_exceeded→InvalidRequest`, `content_policy_violation/refusal/permission_denied→Auth`): the parser checks `error.metadata.error_type` first, falls back to numeric `error.code`, then to HTTP status. HTTP 200 with top-level `error` (provider failure after 200 OK, per vendor "Non-streaming requests" note) is handled identically — body is checked for `error` even on 2xx.

## D4 Load / performance / security / observability

### Load & concurrency
Request rate: at most one POST per dictation (cleanup), one per command/transform. Dictation cadence is human (press-to-talk), so peak concurrency is 1 by UX; the `mutex_` enforces this even if command + transform + cleanup overlap (the mutex serializes them — a second caller waits for the first POST to finish or time out, bounded by the 8000ms transport timeout). No queue holds more than one in-flight request; no unbounded collection (the scripted fake's `requests_` is test-only). History/logs do not accumulate transcripts (see redaction).
Latency profile: p50 is vendor+network (unavoidable, opt-in); p100 is bounded by `min(provider timeout 8000, caller timeout)` + 3s drain grace in the worst stuck case. The engine worker thread is the thread that blocks (W2-IMPR-01 established this is the correct thread per plan red #7); the UI thread never blocks.

### Perf & resource bounds
Body size is `O(len(system_prompt) + len(text))` serialized once via nlohmann; for typical dictations (<4KB) this is negligible. No tokenization, no image handling, no streaming (SSE parsing would need a different transport and is explicitly out of scope). No thread pool, no connection pool (WinHTTP per-request session/connection handles are closed on every return path — see WindowsHttpClient fail lambda; leak behavior is the existing client's, not this provider's). Provider holds no state beyond settings + cancel flag + last outcome (mutex-protected copy).
Complexity: request build and response parse are both O(body size). No O(n²) work, no unbounded loops. Cancel polling is bounded: checked once before Post and once after (no spin loop).

### Timeout & cancel (the hard part, stated honestly)
`IHttpTransport::Post` is synchronous and takes no cancel token. `RequestCancel` can only set an atomic flag. Two consequences, both by design:
- Cancel *before* Post: honored immediately (no request sent, outcome `Cancelled`). This is the deterministic path and is tested.
- Cancel *during* Post: NOT interruptible. The provider cannot abort WinHTTP mid-read. The outer caller already timed out and returned raw; the provider thread remains blocked inside `Post` until the transport's own timeout fires (`HttpRequest.timeout_ms`, WinHTTP resolve/connect/send/receive timeouts). Because DictationCleanup's drain is only 3s, a Post blocked for the full 8000ms will outlive its caller by up to ~5s, then complete and write `LastOutcome` harmlessly. This is the same residual W2-IMPR-01 accepted for LocalLlamaProvider (detached thread preferring clipboard restoration over wedging) — here the thread is the cleanup Worker's thread, not a detached thread, and the block is bounded by 8000ms. Documented in D6 as an open risk; fixing it needs transport-level cancellation (WindowsHttpClient future work outside this write-set — NEED-4, not attempted).
`HttpRequest.timeout_ms` is the provider's knob; it defaults to 8000 (brief) and is clamped to >0 in the request builder so WinHTTP falls back to its 15000 default only when 0 is passed intentionally.

### Security: key custody, egress scope, exfiltration surface
- Key materialization: `OPENROUTER_API_KEY` travels exactly once — main.cpp resolves store→env and passes the string by value into `OpenRouterProviderSettings`. It is then emitted exactly once per request as the `Authorization: Bearer <key>` header value (vendor-mandated). No other header carries it; no optional `HTTP-Referer`/`X-OpenRouter-Title` attribution headers are sent (minimizes fingerprinting; they are optional per vendor docs). The key is never copied into `HttpRequest.body`, never logged, never persisted.
- Redaction layering (defense in depth, STT precedent): `LastOutcome.detail` = `RedactSecret(RedactAuthValues(vendor_message), api_key)`. `RedactAuthValues` masks any `Authorization:` line in echoed text; `RedactSecret` replaces every occurrence of the exact key string with `[redacted]`. Neither the outcome nor any `Log::` line contains the key or the request/response text. Read redaction tests assert key bytes AND 4-byte prefix are absent.
- Egress scope: exactly `POST openrouter.ai:443 /api/v1/chat/completions` with a JSON body containing model + two messages (system prompt + dictated/selected text). Nothing else leaves the machine: no model-discovery GET, no telemetry, no key-check GET `/api/v1/key`. One-way: cloud→local fallback means a failed request never re-sends the text elsewhere.
- SSRF / injection: host/path are compile-time constants, not operator-controlled, so the transport cannot be pointed at an internal endpoint. Model string is operator-controlled but is only a JSON value, never a URL/host. JSON is serialized via nlohmann (no string-concat injection of text into the wire format).
- Abuse / billing: each dictation costs one completion. No request amplification (single Post, no retry loop), no unbounded loop. Rate-limit responses are fail-closed (raw fallback), never retried with backoff sleeps.
- Disk: zero writes in this TU (file-write gate clean). `api_keys.json` custody stays in ApiKeyStore (D3, unchanged).

### Observability
`LastOutcome{error, http_status, detail(redacted), latency, request_id?}` is queryable in-process for tests and future UI badges; a `Log::Warning` is emitted on failure (status/error/latency, no text/key) mirroring Gnani/Muse `LogAttempt` but through `lwf::Log::Warning` instead of `std::cerr` (modernized: app logs go through `Log::.*` with rotation + redaction history; `std::cerr` in STT providers predates the Log ring buffer and is not copied). Success logs at `Log::Info` only if enabled via debug? No — success is silent to keep the log clean; error-path logging is the observability (a silent failure would be a support black hole). `request_id` is the vendor `id` field (`gen-...`) when present, enabling generation-stats lookup `/api/v1/generation?id=` out-of-band by the operator.

## D5 Rollout / rollback / compatibility

Rollout is a config flip behind an existing default: `llm_provider` defaults to `local` (schema, SettingsStore.cpp:69). With the default, the binary behaves exactly as today (D2 invariant 1). Enabling OpenRouter requires three operator actions, none of which migrate any file: (1) set `llm_provider=openrouter` in config.json (or Settings GUI combo — already present), (2) set `openrouter_model` (new additive key; config.json hand-edit today — no GUI control in this task, NEED-3), (3) provide the key via `api_keys.json` `{"openrouter": "sk-..."}` OR environment `OPENROUTER_API_KEY` (restart required in both cases — the key is snapshotted at construction). First dictation after restart exercises the path; the Privacy/About conditional disclosure is live in the same build.
Rollback: `llm_provider=local` + restart. `openrouter_model` is harmless when ignored (additive key preserved on save). `api_keys.json` deletion is harmless (store falls back to env, then to disabled-cleanup). No migration, no `.bak` needed. Git rollback is a straight revert (additive files, no shared-file surgery). Compatibility: `config.json` old files load with `openrouter_model=""` default; new files with the key set load on older binaries as an unknown key (preserved verbatim on save, never dropped). `ILlmProvider` ABI unchanged; no calling code other than main.cpp construction changes.
Gate rollout (C2): `check_no_network.sh` endpoint regex + carve-out land in the same commit as the `.cpp` (standing same-commit rule). Network allowlist is NOT extended (D1 option 1: the TU contains no network-API strings; extending it would falsely claim it performs WinHTTP calls). Report states this deviation explicitly.

1. **Mid-Post cancel not interruptible** (D4). Caller has already fallen back, so user-visible correctness holds; only a bounded background block (≤8s) remains. Fix needs transport cancellation (WindowsHttpClient) — NEED-4. Likelihood if vendor hangs: low; impact: one cleanup worker holds a thread for seconds. Reproducible in tests via a blocking fake (P-?? test).
2. **Vendor unverified against live API** (R-02 scope). Honest status: contract VERIFIED-from-docs, UNVERIFIED-against-live.
