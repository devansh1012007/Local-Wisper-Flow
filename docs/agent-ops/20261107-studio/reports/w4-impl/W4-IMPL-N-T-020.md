## 2. Root cause and context summary

Root cause: `MainWindow::DrawScratchpadPage` is a stub that prints `Not available yet.` (src/ui/MainWindow.cpp:961-964). There is no Scratchpad page UI, no editor window, and no path for a user to create, open, pin, search, delete, or dictate into notes, despite Wave-1 `NotesStore` persistence and Wave-2 `ScratchpadBuffer`/`ScratchpadInjector` + `scratchpad_flow_bar` + Overlay note button being ready. The fix is architectural mirroring of the existing two-window shell and Wave-3 widget system, not a reopening of the store or engine seams: page lives in the Full window render, editor lives in its own OS window and ImGui context, persistence goes through `NotesStore`, dictation goes through Wave-2 buffer only when the editor is focused. Verified: stub count is five `Not available yet.` in MainWindow.cpp including Scratchpad [tests/test_overlay_settings_ui.cpp:640]; `NotesStore` API is Create/Update/Delete/Pin/Unpin/List/Search/Get/Restore/Reload/Size [src/core/NotesStore.h:44-55]; Wave-2 target is `ScratchpadBuffer::Append/Text/Clear` + `ScratchpadInjector` [src/core/NotesStore.h:11-30] with engine flag `SetScratchpadTarget(bool)` suppressing stats [src/core/DictationEngine.cpp:641] and Wave-2 tests proving buffer-only delivery [tests/test_scratchpad_target.cpp:90-149]; `scratchpad_flow_bar` defaults OFF hot_apply true [src/core/SettingsStore.cpp:65, tests/test_scratchpad_target.cpp:187-204]; Overlay note button is gated by that key and pokes `dirty_` via `poll_note_hover_` [src/ui/Overlay.h:92, src/ui/Overlay.cpp:312-328, 400-435]; main drain handles `OpenScratchpad` by only `full.SetVisible(true)` (editor not created) [src/main.cpp:615-618]; widgets are `ToggleSwitch`, `LightButton`, `IconButton`, `BadgeBeta` [src/ui/widgets/Widgets.h:15-22] with StudioPalette tokens and metrics [src/ui/theme/StudioPalette.h:24-69] and dark palette frozen [src/ui/theme/ThemePalette.h:46-61].
