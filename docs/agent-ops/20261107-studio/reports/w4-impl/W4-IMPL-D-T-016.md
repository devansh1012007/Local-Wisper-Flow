## 3. Phased changes executed

### Phase 1 — portable page logic (src/ui/pages/DictionaryPage.h, new)
DECISION — header-inline state/helpers: the header carries `DictionarySort`, `DictionaryTab`, `DictionaryPageState`, and inline helpers operating only on `DictionaryStore` + optional `PersonalDictionary*`. This keeps test coverage in lwf_tests exact (lwf_tests links `lwf_core` only, never imgui) while `Draw` stays in the .cpp. Sibling wave-4 pages use the same split.
- `VisibleEntries(store, state)` — search filter via `store.Search` (case-insensitive phrase+replacement), hides the pending-delete entry, then `stable_sort` per sort mode with the page-wide starred-first invariant: NameAsc → starred, phrase A-Z (case-insensitive), id asc; Newest → starred, updated desc (mirrors the store's `SortedCopy`); MostUsed → starred, usage_count desc, updated desc, id desc. Tie-breaks are deterministic; `std::stable_sort` keeps the store's newer-first order for equal keys.
- `TopPhrases(store, limit)` — entries with `usage_count > 0` sorted usage-desc, phrase-asc, id-asc; the banner chip loop caps at 5.
- `VisibleBanner(store, state)` — `Size()==0` always visible (fresh-state invitation); otherwise `!banner_closed`. Close X hides until the list goes empty again, matching the brief wording exactly.
- `SubmitAdd/SubmitUpdate(store, dict, ...)` — `Add/Update` error passes through verbatim (inline `"Word already exists."`), then `Save()`, then `dict->Reload()` on success (D-OP2 without restart). Save failure surfaces `"Could not save dictionary."` and leaves the in-memory edit intact (the Add pre-validates emptiness/cap, so this path is IO failure only).
- Deferred delete: `RequestDelete(store, state, id, now)` stashes `{entry, delete_at = now + toast_dwell_s}` without touching the store; the entry is hidden from the list only. `UndoPendingDelete` clears state (nothing to restore). `CommitExpiredPending(store, state, now)` commits `Remove + Save` at `delete_at`. A second delete while one is pending commits the first immediately (single-undo invariant). `toast_dwell_s` is the same 5.0s the Wave-3 `Toast` widget draws, so page and widget stay in lockstep.
INVARIANT: `dictionary.json` only ever changes via `DictionaryStore` (atomic v2 save + `.bak` once on migration + `.bad` on corrupt). The page adds no file-writing path of its own.
