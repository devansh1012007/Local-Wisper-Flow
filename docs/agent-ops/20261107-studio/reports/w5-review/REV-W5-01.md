## 4. Findings

### R-W5-001 [MAJOR] Mid-Post cancel wedges the shared cleanup worker; next `Process` head-of-line blocks up to 8000ms

- Location: `src/llm/OpenRouterProvider.cpp:299-380` (`mutex_` held across `transport_.Post(request)` at `:322`; cancel checked only before/after `:308/:351`) + `src/core/DictationCleanup.cpp:193-197` (2000ms `wait_for` → `RequestCancel()` → 3s drain → raw) + `src/main.cpp:394` (provider timeout hard-coded 8000, ignores `cleanup_timeout_ms`).
- Evidence: `GateTransport` test proves cancel is observed only *after* the fake’s `Post` is released. In production `WindowsHttpClient::Post` is a blocking WinHTTP call with no cancel token (`WindowsHttpClient.cpp:67-167`); `RequestCancel` is `cancel_requested_.store(true)`. Sequence for a hung vendor response on the cleanup path: caller times out at 2000ms, cancels, drains 3000ms, returns raw at ~5000ms — but the worker thread is still inside `Post`, holding `mutex_`. The **next** dictation’s `Process` blocks on `mutex_` until that Post finishes or hits 8000ms. The D6 claim “no correctness issue (caller fallback authoritative)” confuses *this* dictation’s correctness (held) with *next* dictation’s liveness (not held).
- Why it matters: human dictation cadence masks single hangs, but two consecutive slow/hung responses stack 5–8s of UI-visible latency per dictation, and command/transform callers (8000ms budget) share the same mutex. This is a reliability degradation, not a crash; it is bounded, but the bound is operator-visible.
- Recommended fix (root-cause, when W-INT or a follow-up owns the seam): make the timeout budgets coherent — pass `cleanup_timeout_ms` (and the engine’s per-caller timeout) through to `HttpRequest.timeout_ms` (provider holds the knob; callers hold the deadline) and, properly, grow `IHttpTransport` with a cancellation handle so `Post` can abort WinHTTP. Until then, at minimum do **not** hold `mutex_` across the network wait for *subsequent* callers: e.g., `try_lock` + early `Cancelled`-style rejection, or snapshot settings + release lock before `Post`. Do NOT “fix” with a sleep/retry. For this review, recorded as accepted-risk with the head-of-line extension made explicit (P/O NEED-4 already tracks transport cancel).

### R-W5-004 [MINOR] Status 504/Timeout and 412 fall through to generic categories

- Location: `src/llm/OpenRouterProvider.cpp:64-87 StatusToCategory` (`408→Timeout`, `>=500→Server`, `400–499→InvalidRequest`).
- Evidence: vendor typed table (fetched this review) maps `timeout→504`, `precondition_failed→412`. 504 without an `error_type` (or with a masked 500-style message) classifies as `Server`; 412 classifies as `InvalidRequest` (correct outcome, but the report’s D3 row listing 412 as a deliberate InvalidRequest row is achieved only via the generic 4xx bucket, not an explicit pin — no test case for 412). When `error_type` is present the category self-corrects (`ErrorTypeToCategory("timeout")→Timeout`), which is why tests don’t catch it.
- Why it matters: timeouts lose their identity in metrics/logs exactly when the vendor masks the message (500-class masking). No user-visible failure-path difference (all map to empty→raw).
- Recommended fix: add `504→Timeout` (and optionally explicit `412→InvalidRequest`) to `StatusToCategory` with two pinned test cases; keep `error_type` precedence as-is.

### R-W5-005 [MINOR] `BuildRequest().dump()` outside try breaks the “never throws” contract in theory

- Location: `src/llm/OpenRouterProvider.cpp:148-174` + `Process:316` (`HttpRequest request = BuildRequest(...)` outside the `try` at `:321`).
- Evidence: nlohmann `dump()` throws on invalid UTF-8 sequences and on OOM. `Process` catches `HttpTransportError`/`std::exception`/`...` around `Post` only. Callers (`DictationCleanup:199-205` catches; engine/command wrappers catch) ultimately contain it, so user impact is nil, but the provider’s own stated invariant (D2#4 “Process never throws for vendor/transport conditions”) is overstated: it omits serialization-throw as a condition. (Prove-it-wrong attempt: passed bytes-invalid-UTF-8 text `"\xFF"` through a local `dump` — throws; via `Process` it would unwind to the caller.)
- Recommended fix: either wrap `BuildRequest` in the same try (mapping to `Malformed`/`Network`) or narrow the invariant wording to “never throws for wire failures; serialization throws are caller-handled (as in LocalLlamaProvider)”. Former is preferable (5 lines).

### R-W5-006 [MINOR] `choices[0].error` (non-streaming mid-generation provider error) ignored — falls to `Malformed`

- Location: `src/llm/OpenRouterProvider.cpp:233-297 ParseSuccessBody` checks top-level `error` (`:253-259`) but never `choice.error` (or `choice.message.refusal`).
- Evidence: vendor skin docs (fetched this review) describe non-streaming provider errors embedded as `choices[0].error{code,message,metadata.error_type}` alongside partial `message.content` (and, for refusals, successful `message.refusal` with `finish_reason: content_filter`). Current code in that shape either returns the partial content as a clean success (if content present) or returns `Malformed` “no content field” (if content absent). Both are safe fallbacks (guards/validators still apply) but lose typed-error identity.
- Why it matters: observability only; recoverability is unaffected. Would matter only if a caller later branched on `LastOutcome.error` to decide retryability.
- Recommended fix: check `choice.contains("error") && !is_null()` and route through `ClassifyFailure`, mirroring the top-level handling. Do not invent partial-content extraction when `error` is present (fail closed, as today).

### R-W5-007 [MINOR] `error_type` allowlist is hand-copied; 402/Auth + 5xx split will drift from STT’s table

- Location: `src/llm/OpenRouterProvider.cpp:36-62 ErrorTypeToCategory` (26 vendor strings) + `StatusToCategory`.
- Evidence: O D6 Risk #6 already names drift from `src/stt/cloud/HttpStatus.cpp`. The LLM table currently mirrors the vendor table exactly (verified this review against the live typed-code tables), but there is no cross-pin asserting LLM-vs-STT table equality, and the LLM classifier lives far (by layering choice) from `HttpStatus.cpp`.
- Why it matters: the next vendor/transport status addition updates one table and not the other.
- Recommended fix (DO-LATER): a single cross-table test that feeds every status in the vendor table through both classifiers and notes deliberate divergences (402/Auth-by-billing vs 5xx) in comments. No abstraction now.

### R-W5-008 [MINOR] Cleanup `GuardRejections` conflates provider transport failure with guard rejection

- Location: `src/core/DictationCleanup.cpp:158-177 ApplyGuards` (empty → `reject()` increments) + `tests/test_openrouter.cpp` failure case pinning `GuardRejections()==1`.
- Evidence: provider returns empty on auth/timeout/network; cleanup sees empty and counts a “guard rejection”. `LastOutcome` disambiguates in-process, but the counter does not. O report discloses this as accepted consequence of the no-throw empty contract.
- Why it matters: telemetry/Insights consumers of `GuardRejections` over-count model quality rejections.
- Recommended fix: DO-LATER — add a provider-failure counter alongside (e.g., `DictationCleanup::ProviderFailures()`) driven from `LastOutcome` when the provider is the concrete OpenRouter type, or accept and document the conflation on the counter’s doc comment. No behavior change now.

### R-W5-009 [NIT] `clear` + `Load`/`Save` tombstone: correct, but failure mode is silent-ish

- Location: `src/core/DictionaryStore.cpp:408-450 Clear` (persists `{"schema_version":2,"entries":[]}` via tmp+rename; logs warning on write failure).
- Evidence: all three tombstone tests pass (`delete-all clear before first visit`, `clear leaves an empty file so reload and save stay empty`, `genuine first-run still seeds`). Ordering in `MainWindow::DeleteLocalData:703-723` (file removed *then* `dictionary->Clear()` recreates the tombstone) is the only correct order. On write failure the store stays empty in RAM but the file stays missing → next `Load` re-seeds `btw`. Failure is logged but not surfaced in UI. Acceptable for a best-effort tombstone; noted for completeness. Positive: `StatsStore::Clear` precedent (`"{}"`) is mirrored correctly.
