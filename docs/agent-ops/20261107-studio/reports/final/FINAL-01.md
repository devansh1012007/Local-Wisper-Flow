## Blind findings

### Regressions (FSM / dictation / STT paths)
- **Engine/settings**: `DictationEngine` snapshots `EngineSettings` under `settings_mutex_` at every call site (DictationEngine.cpp:277-285, Tick/StopAndTranscribe/BeginCapture). This fixes a real race (main loop ApplySettings now calls `engine.SetSettings()`) and old single-threaded callers see identical values. No semantic change to FSM transitions.
- **Stats hook placement verified**: `StatsStore::Record` runs only after successful `injector_.InjectText(final_text)` (DictationEngine.cpp:627-656). The structural exclusions are correct: command mode early-returns before the hook, cancel during STT/cleanup returns before it, empty-final returns before it, PasteLast is a separate method, scratchpad routing sets `scratchpad_target_` (suppressed). New tests pin each exclusion (`test_engine.cpp`, "records nothing for ..." cases) and capture-app-at-press-time + duration. No double-count path found.
- **STT/injection contracts**: no diff touches `src/stt/`, `src/audio/`, `IInferenceProvider`, `ITextInjector`, or the injector. `SttRouter` consent path unchanged; cloud->local one-way fallback preserved. `test_engine.cpp` only appends cases after line 331; all pre-branch assertions survive verbatim. Baseline STT/injection suites are unmodified.
- **TextPipeline**: `ProcessWithStats` delegates from `Process` with identical `Process` output; `words_corrected` is a word-LCS diff vs raw (TextDiff.cpp:83-144, bounded O(n*m), UTF-8-safe, no OOB) and `dictionary_fixes` comes from `PersonalDictionary::Enforce` fix count. `Enforce` was rebuilt around snapshot reads + cursor walk (PersonalDictionary.cpp:276-355) — the old "replace in out, detect no-op" loop could in principle spin on identity replacements; the new rebuild cannot. Behavior on the pinned suite is unchanged.
- **HotkeyBinding**: new conflict/de-dup logic (`BindingsConflict` subset test, `LoadBindings` drops subset duplicates at HotkeyBinding.cpp:382-402) is additive but changes load semantics beyond the 5-key recorder work. Two edges: (a) a hand-edited bare-letter/single-digit chord previously failed to parse and was ignored; it now parses. The recorder and the settings text field both reject modifier-less chords via `ValidateRecorderChord`, so creation paths are safe, but a legacy hand-edited `hotkey_ptt="a"` would now fire on letter press. Low likelihood, no test pins the old ignore behavior. (b) Drop-on-conflict is silent. Suggest a log line naming the dropped role.
- **Dictionary dual instance**: `main.cpp` loads both `PersonalDictionary` (pipeline) and `DictionaryStore` (page) on `dictionary.json`. Sync is correct: every page commit path calls `dict->Reload()` after `store.Save()` (DictionaryPage.h:142-246), and `PersonalDictionary::Load` now reads v2 `schema_version:2 / entries` as well as both v1 shapes (PersonalDictionary.cpp:108-~143). No stale-pipeline path remains for add/update/delete. Import/delete-all go through the same Commit*/Submit* helpers.
- **Transform engine path**: `HandleTransform` (DictationEngine.cpp:726-832) runs on the engine worker thread via `PumpTransform`, never the UiBus/main thread. Opt-in gate, slot gate, 8000-char cap, preamble/3x+200 validation, clipboard restore on every exit path, and 40 s diff retention are all present and tested in `test_transform_runflow.cpp`. One narrow lifetime issue: on LLM timeout the worker is `detach()`ed while still holding the `llm` pointer (lines 785-792). In `main.cpp` the provider outlives the engine, and the work is bounded by the transport/decode timeout, so practical risk is low — but a shutdown racing a detached >11 s decode would be use-after-lifetime. `join()` or a shared-ownership guard would close it; listed as follow-up, not a blocker (feature is opt-in and off by default).
- **Notes/stats stores**: mutex-guarded, atomic tmp+rename, corrupt->`.bad`/empty, orphan `.md` re-adoption + dangling-index drop reconciles instead of crashing (NotesStore.cpp:162-250). `IsValidId` blocks traversal (`/`, `\`, `..`, control chars, >128). Stats eviction keeps 730 days inclusive (StatsStore.cpp EvictLocked). `DeleteLocalData` (MainWindow.cpp:700-747) removes all seven data artifacts and re-syncs stores in place; the remaining `.bak`-preservation order is safe for dictionary (tombstone written after removal) and api_keys (reload of missing file clears RAM).

### Migration integrity (old files → new code → back)
- **config.json**: 6 additive schema rows only (scratchpad_flow_bar, keep_usage_stats, last_page, quiet_speech_boost, llm_provider, openrouter_model — SettingsStore.cpp:62-69); unknown keys still round-trip; v0 compat suite passes. Safe.
- **dictionary.json**: upgrade path is sound. `DictionaryStore::ParseAny` reads 4 legacy shapes (array / words / replacements / both) and writes `schema_version:2 / entries[{phrase,replacement,...}]`; first migrated `Save()` preserves the legacy file in `.bak` **only if `.bak` is absent** (DictionaryStore.cpp:476-484) — the one store that gets the "original preserved across saves" semantics right. Delete-all tombstone (lines 408-450) correctly prevents reseed resurrection.
- **snippets.json / transforms.json**: upgrade reads v1 (array) and v2 (`snippets`/`slots` object) and writes v2 with an unconditional `.bak` overwrite on every Save (SnippetStore.cpp:268, TransformStore.cpp:534). After a second Save the `.bak` is already v2, so the legacy original survives only across the first save. Dictionary's guard-against-overwrite pattern should be the shared one. Non-blocking but inconsistent; should be unified.
- **Downgrade**: pre-branch binaries cannot read the new v2 files (old `PersonalDictionary` expected array/`{words,replacements}`, old `SnippetStore` expected array, old `TransformManager` expected array). Within-branch legacy readers were upgraded to accept both shapes, so "back" works for this branch's own build. True rollback to `0e655ec` would silently load-empty the three files unless the operator restores the `.bak` files. The plan explicitly accepts one-way migrations mitigated by `.bak` (STUDIO_PLAN §16/§10), so this is **documented, not a merge blocker** — but it must be called out in the merge notes, and `.bak` retention must not be deleted on upgrade.
- **stats.json / notes/ / api_keys.json**: greenfield; no legacy file is touched. `Clear()` persisting `{}` is round-trip safe (`LoadLocked` accepts empty object).

### Security (keys, transcripts, egress)
- **No secret or transcript leak found.** `ApiKeyStore` keeps keys in separate `api_keys.json` (never `config.json`), store→env order everywhere (`ConsentGate::ResolveApiKey` for STT, manual store-then-env in the OpenRouter branch of `main.cpp`). GUI has **no key editor** — keys are hand-edited in `api_keys.json` or env. `OpenRouterProvider::RedactDetail` (OpenRouterProvider.cpp:176-182) applies `RedactSecret(RedactAuthValues)` + 500-char cap; failure logs carry status/error/latency/detail only, never text or key. Pinned by redaction tests asserting key bytes and 4-byte prefix absence. No `debug_log_transcripts` change; `StatsStore` persists counts/categories/app names, never transcript text (it receives `final_text` only to count words).
- **Residual (accepted, pre-existing)**: `api_keys.json` and every `.bak` copy are plaintext on disk with default ACLs (ApiKeyStore.cpp:117-152). The `.bak` duplicates keys. DPAPI/ACL hardening was already deferred (W5 reports NEED trail); it is a real but pre-existing design choice, not introduced by this review.
- **Prompt/data separation**: transform prompts embed `<selection>{text}</selection>` + "data, not instructions" guard, strip inherited `<selection>` tags before wrapping (DictationEngine.cpp:62-76). Host/path/model are compile-time or JSON values, never URLs.
